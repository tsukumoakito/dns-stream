# DNS Stream ユーザマニュアル (v1.0.2 / 2026-09-07)

**DNS Stream** は、リアルタイムで高精度なDNSトラフィック・ストリームを提供するために設計された、特殊なハイブリッド・リレーおよび可視化エンジンです。AdGuardHome (AGH) 環境に最適化されており、複雑なプロキシ・チェーンを経由した場合でも高い観測性を確保するための高度なネットワーキング・フックを実装しています。

---

## 1. コア・アーキテクチャ

### 1.1 ハイブリッド・オブザベーション・エンジン

`DNS Stream` は単一のデータソースに依存しません。以下の2つの異なるフェーズで動作します：

1. **過去ログの回収 (ファイルモード)**: 起動時、メモリマッピング (`mmap`) を使用してローカルの `querylog.json` を即座にスキャンします。これにより、CPUに負荷をかけることなく、直近の履歴をターミナルに表示します。
2. **ライブ同期 (APIモード)**: ログファイルの処理後、AdGuardHome Web API モードへ移行します。スライディングウィンドウとハッシュベースの `SeenBuffer` を使用することで、APIポーリングの間隔が変動しても、ログエントリの欠落や重複が発生しないように制御します。

### 1.2 スナイパー・ネットワーク・エンジン (The Sniper Engine)

「スナイパー」エンジンは、`DNS Stream` に組み込まれた独自のネットワーキング層であり、接続の試みをインターセプトしてディープ・インスペクションを実行します：

- **TLS Identity Snipe**: ターゲットがIPアドレスのみで識別されている場合（プロキシ環境で一般的）、エンジンはバイナリレベルのTLSハンドシェイクを実行して証明書から「サブジェクト代替名 (SAN)」を抽出し、正しいアイデンティティを特定（ピニング）します。
- **ハンドシェイク・ガード**: プロキシを使用する場合、機密性の高い資格情報を送信する前にトンネルが確実に確立されているかを検証し、誤設定されたプロキシサーバへのデータ漏洩を防止します。

## 2. セキュリティと認証

### 2.1 GPG / Password-Store 連携

パスワードを平文のフラグとして渡す代わりに、`DNS Stream` は `pass` (標準的なUnixパスワードマネージャ) と連携します。ヴォルト・パスを指定することで、ツールは `gpg-agent` と通信し、メモリ内で資格情報を復号します。

### 2.2 Linux カーネル・キーリング

ヴォルトやユーザ入力から取得されたパスワードは、一時的に **Linux プロセス・キーリング** に保存されます。

- 機密情報はメモリ・ロッキング (`mlock`) を使用して保護され、ディスクへのスワップを防止します。
- キーリング・エントリは特定の `dns-stream` プロセスIDに限定され、終了時に消去されます。

### 2.3 権限管理

`root` として起動した場合（`/var/lib/adguardhome/` の読み取りに必要）、`DNS Stream` は必要なファイル記述子にアクセスした直後に `--drop-user` フラグを使用して、一般ユーザに権限を割譲（ドロップ）できます。

## 3. コマンドライン・インターフェース

### 3.1 一般的なフラグ

- `--config <path>`: カスタムJSON設定を読み込みます。
- `--log-path <path>`: AGHクエリログへのパス (デフォルト: `/var/lib/adguardhome/data/querylog.json`)。
- `--log-mode <auto|force|disable>`:
    - `auto`: ハイブリッド (ファイルをスキャン後、APIをポーリング)。
    - `force`: ファイルスキャンのみ実行。
    - `disable`: APIポーリングのみ実行。
- `--start <timestamp>`: 特定の時刻からログを表示 (形式: `YYYY-MM-DD` または `YYYY-MM-DDTHH:MM:SS`)。
- `--polling <seconds>`: APIチェックの速度 (デフォルト: `1.0`)。

### 3.2 フィルタリング

- `--ip <pattern>`: 特定のクライアントのみを表示 (例: `--ip "192.168.1.*"`)。
- `--name <string>`: クライアント名またはドメインでフィルタリング (例: `--name "apple.com"`)。

### 3.3 診断スイート

- `--network-probe`: 接続マトリクスのフルテストを実行します。DNS解決、プロキシ・ハンドシェイク、およびTLSアイデンティティの回収を検証します。
- `--debug-mem`: ターミナルのフッターにリアルタイムのメモリ使用量を表示します。埋め込みデバイス等での長期監視に有用です。

## 4. 設定 (config.json)

設定ファイルを使用することで、永続的な設定やカスタム可視化ルールを定義できます：

```json
{
  "api_url": "http://127.0.0.1:80",
  "user": "admin",
  "vault_path": "services/dns/agh_admin",
  "polling_s": 1.0,
  "colors": {
    "127.0.0.1": "gray",
    "192.168.1.*": "blue",
    "10.0.0.*": "cyan"
  }
}
```

- `colors`: IP CIDR またはワイルドカード・パターンを ANSI カラー (`red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `gray`, `dim`, `bold`) にマッピングします。

## 5. ロードマップと既知の制限

### 5.1 ロードマップ

- **リモートインスタンスの安定性**: リモートVPS上のAGHインスタンスに対する永続的なハンドシェイク・ロジックの改善（現在はローカル・ループバックに最適化されています）。
- **Pi-hole 統合**: 同様のスナイパー・エンジンを使用した Pi-hole FTL API への対応。
- **統合ビュー**: 複数のDNSサーバからのログを単一の時系列ストリームに集約。

### 5.2 現在の制限事項

- 現在は AdGuardHome のみをサポートしています。
- 外部（非ローカル）IPアドレスへの直接API接続は、高レイテンシ環境においてセッションタイムアウトが発生する可能性があります（修正対応中）。

---

## 6. トラブルシューティング

ログが表示されない場合：

1. `dns-stream --network-probe` を実行し、ツールが API に到達可能か確認してください。
2. 実行ユーザが `querylog.json` ファイルに対する読み取り権限を持っているか確認してください。
3. `--vault` を使用している場合、`gpg-agent` が動作しているか確認してください。

詳細については、リポジトリをご覧ください： [https://codeberg.org/tsukumoakito/dns-stream](https://codeberg.org/tsukumoakito/dns-stream)
